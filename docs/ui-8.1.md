# ANATOMAI UI 8.1 — Разбор вопросов

Ветка `feature/anatomai-question-review-8.1` создана от `50d53111d37428aee8e297047be92b74d1b94809` (Home Layout 8.0). Main и опубликованный Preview не изменялись.

## Реализация

Из конкретной темы новая кнопка «Разбор вопросов» открывает отдельный справочник. Существующие «Обучение», «Экзамен» и нейтральный предпросмотр темы сохранены.

На странице — название темы, поиск по формулировкам, количество вопросов и вертикальный список карточек с исходными номерами. Все варианты открыты сразу. Правильные ответы отмечены светло-зелёным фоном и галочкой, остальные нейтральные. Нажимать на ответ не требуется: вариантов как интерактивных кнопок, проверки, оценки и «Следующего вопроса» здесь нет. Объяснение доступно через компактный details только при наличии в исходных данных. Для некорректного/отсутствующего индекса правильный ответ не придумывается.

Использованы существующие токены палитры, белые карточки с тонкой границей и радиусом 18 px. Верхняя область с поиском остаётся над прокручиваемым списком. Экран входит в существующий test-flow AppShell, учитывающий Telegram safe-area один раз; нижняя навигация на нём скрыта как на теме и вопросе.

Поиск учитывает регистр, ё/е и лишние пробелы, ищет только в тексте вопроса. Нумерация после фильтрации остаётся исходной. Для больших банков первоначально монтируется 30 карточек, «Показать ещё» добавляет следующую порцию; новый запрос сбрасывает лимит и прокрутку списка. Все результаты доступны без изменения порядка банка.

## Данные и ограничения функций

- Банк вопросов и ответы читаются из существующего `questionsForTest`, без новых медицинских данных, backend или API.
- В текущем `TestQuestion.correctAnswer` один индекс. Read-only модель справочника также принимает явный массив индексов: несколько верных вариантов выделяются одновременно, без догадок по тексту ответа. Этот случай проверен на отдельной тестовой фикстуре; реальный банк и одиночная модель тестового движка не менялись.
- Механизма сохранения избранного в проекте нет. Неработающих звёздочек и фиктивного хранилища не добавлено.
- Справочник не создаёт попыток, не начисляет результаты/XP и не записывает историю.

## Возврат и экзамен

Справочник использует существующий `useTelegramBackButton`, а в браузере показывает внутреннюю «К теме». В подтверждённом Telegram-контексте дублирующая кнопка не отображается. Browser history back/forward работает между темой и справочником.

Тема сохраняет своё состояние «Показать все» и позицию прокрутки при переходе в разбор и обратно. Пока справочник активен, hook темы отключён: нативным callback владеет один экран. При закрытии подписки очищаются.

При запуске обучения/экзамена справочник размонтируется: зелёные ответы не остаются скрытыми в DOM экзамена. Движок, оценка, пропуски, завершение, повтор и разбор ошибок результата не изменены.

- `npm run typecheck` — успешно.
- `npm test` — 35/35 тестов: прежние 32 и 3 новых набора проверок read-only модели (один/несколько индексов, отсутствие вымышленных ответов, поиск/нумерация, большой банк/порции).
- `npm run build` — успешно.
- `node tests/ui81.mjs` — 9 сценариев 375/390/430 × browser/mock Telegram expanded/fullscreen: все варианты и правильные ответы видны сразу, нейтральные неправильные, поиск/нет совпадений, объяснение, сохранение темы, Back/forward, единственный callback, safe-area, отсутствие горизонтального переполнения, обучение и отсутствие раскрытия ответов в экзамене.
- Ещё 3 UI-сценария на тех же ширинах с тестовыми данными: несколько правильных, отсутствующее объяснение, пустой банк, 200 длинных вопросов/ответов, 30 → 60 карточек, поиск последнего вопроса с номером 200, короткий экран высотой 400 px. Тестовые HTML/TSX не входят в production entry.
- `VIEWPORT_JOURNEYS_ONLY=1 CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node tests/viewport.mjs` — успешно: полные обучение/экзамен, пропуск, результаты, разбор ошибок, повтор, сохранение вкладок/поиска, reduced-motion.
- `git diff --check` — успешно. Банк вопросов, types/движок, Telegram SDK, Главная, промобаннеры, статистика, профиль и конспекты не менялись.

Основной UI проверен на локальной production-сборке `127.0.0.1:4796`; расширенные тестовые случаи — через отдельный Vite fixture server `127.0.0.1:4798`. Это не работающий Preview. URL UI-теста можно изменить через AFTER_URL/FIXTURE_URL.
