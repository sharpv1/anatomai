# ANATOMAI — пользовательская часть: аудит перед завершением (этап 6c)

Дата: 2026-11-22. Рабочая ветка: `feature/anatomai-user-app-final`.

## Проверено по исходникам и ранее сохранённым отчётам

- `src/main.tsx` выбирает `BackendApp` только при `backendConfig.enabled`; в `.env.example` флаг `VITE_MEDEXA_BACKEND_ENABLED=false`. Без явного opt-in пользователь увидит legacy-приложение, а не Backend 2.0.
- `src/backend/BackendApp.tsx` реализует отдельную серверную навигацию Home, Tests, Notes, Profile, Statistics, Topic, Review, Attempt. При готовой Identity используется `AttemptController` на подтверждённый UUID владельца.
- `src/backend/screens.tsx` читает серверные Home, рекомендации, каталог, темы, конспекты, статистику, историю и достижения. Каталог поддерживает поиск и пагинацию.
- `docs/frontend-attempts-6b.md` фиксирует реализованные Learning/Exam, resume, idempotency, защищённый review и E2E HTTPS+PostgreSQL 16. Это результаты предыдущего этапа, а не повторно выполненные проверки текущей ветки.
- `docs/frontend-integration-6a.md` фиксирует read-only API и отдельную серверную ветку UI.

## Подтверждённые ограничения

1. Серверный повтор **только ошибочных вопросов** отдельным режимом не реализован; есть защищённый разбор и повтор набора. Решить, является ли это блокером первого релиза.
2. Файловые вложения конспектов не имеют полноценного пользовательского просмотра/скачивания; текстовые конспекты поддерживаются.
3. Неподтверждённый offline-ответ после полного закрытия приложения не восстанавливается.
4. Настоящий Telegram iOS WebView и Safari на устройстве не проверены.
5. Режим Backend 2.0 выключен по умолчанию; для проверки нужен отдельный same-origin HTTPS стенд, корректные cookie, CSRF и Telegram HMAC. Нельзя подключать локальный тестовый клиент к Production API.
